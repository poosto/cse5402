⏺ For floats, partial_cmp returns None whenever either side is NaN:

  1.0_f64.partial_cmp(&2.0)          // Some(Less)
  1.0_f64.partial_cmp(&f64::NAN)     // None
  f64::NAN.partial_cmp(&f64::NAN)    // None

  NaN isn't less than, greater than, or equal to anything, including itself. So
  "incomparable" is the only honest answer, and that's what None means.

  How this connects to PartialEq

  eq returns a plain bool, so it has no None to return. Rust treats "can't
  compare" as "not equal", which is why NaN == NaN is false. The comparison
  operators work the same way. <, >, <=, and >= are all built on partial_cmp,
  and they return false when it gives None. So with a NaN on either side, every
  one of them is false.

  That's exactly why floats can't be Eq or Ord:
  - Not Eq: x == x fails when x is NaN, so equality isn't reflexive.
  - Not Ord: cmp has to return an Ordering every time, and there's no correct
    Ordering for NaN.

  This is also why vec_of_f64.sort() won't compile. You have to write
  sort_by(|a, b| a.partial_cmp(b).unwrap()) and accept that it panics on NaN. Or
  you can use f64::total_cmp, which gives NaN a fixed place in the order.

  For your Player

  A Player always has an answer: it's either silent or it has a first line
  number. So partial_cmp never needs None, and wrapping cmp in Some is correct.
  Your ReadMe paragraph already describes this correctly, including the four
  states and "cannot be compared means unequal".
