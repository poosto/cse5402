  script_config is a &ScriptConfig, so the loop yields &(bool, String). The &
  pattern tries to copy the tuple out of the reference. bool is Copy, so that
  part is fine, but String isn't. You'd get E0507, "cannot move out of a shared

  - Bind by reference: for (is_new_scene, scene_title) in script_config. With
    match ergonomics, is_new_scene is a &bool and scene_title is a &String.
    You'd then need *is_new_scene in the if, and title = scene_title.clone();
    (or title.clone_from(scene_title)).

    and borrows the String.

  String. Also, the spec has you create a fragment only when the bool is false,

❯ what is neat is that lines 38-39 are safe for sure in rust, but in smthn like 
  cpp could be dangerous if that ref is stored internally                       

⏺ Yes, and Rust guarantees it from the function signature alone, without looking
  inside new.

  Why Rust can promise this. SceneFragment::new(title: &str) -> Self returns a
  SceneFragment with no lifetime parameter. A struct with no lifetime parameter
  can't hold a borrowed &str, so new has to copy the title, which is what
  .to_string() does. Once new returns, the borrow of title has ended, and
  clearing or reassigning it at line 39 can't affect the fragment.

  Suppose it had been written to store the reference, as struct 
  SceneFragment<'a> { title: &'a str, … }. The compiler would then reject your
  loop in two places:
  - Line 39 would fail with E0506, "cannot assign to title because it is
    borrowed". The fragment would still be holding a borrow of it.
  - self.fragments.push(fragment) would require the borrow to outlive
    process_config. But title is a local that's dropped when the function
    returns, so you'd get E0597, "title does not live long enough".

  The C++ equivalent fails silently. Say it were written as SceneFragment(const 
  std::string& t) : title_(t), with a const std::string& or std::string_view
  member. Then:
  - title = "" makes every fragment that still refers to it see the new
    contents. With string_view, the assignment can also reallocate, leaving the
    view pointing at freed memory.
  - When process_config returns, title is destroyed, and every stored reference
    dangles. The code compiles cleanly, and it might even print correctly until
    the memory gets reused.

  In C++ you'd catch this by reading the constructor, or with a sanitizer at
  runtime. In Rust, the signature shows whether the struct can keep the
  reference, and the borrow checker enforces it at the call site. This would fit
  well in the "insights and observations" part of your ReadMe overview, or in
  the Scene Fragments section, next to the move/borrow issue you just ran into
  on line 34.

⏺ Slice patterns are a good fit here, but arms 3 and 4 need fixing.

  Arm 3 matches every non-empty line. [scene, rest @ ..] has no guard, and ..
  can match zero elements. So hamlet_ii_1a_config.txt (one token) and foo.txt 
  extra both land there, as well as real [scene] Title lines. The name scene is
  just a binding that takes whatever the first token is. It doesn't check that
  the token is [scene].

  Arm 4 can never be reached. Arm 3 already covers everything it would match.
  Once the old code below it is gone, rustc will warn unreachable pattern, and
  you need zero warnings.

  Arm 2 is correct. Because it comes before arm 3, a lone [scene] never gets as
  far as arm 3. So once arm 3 checks for the directive, its rest will always be
  non-empty.

  A cleaner option: a &str constant can be used directly as a pattern, so you
  don't need guards:

  const SCENE_DIRECTIVE: &str = "[scene]";
  ...
  match words.as_slice() {
      [] => ...,
      [SCENE_DIRECTIVE] => ...,
      [SCENE_DIRECTIVE, title @ ..] => ...,
      [config_file, extra @ ..] => ...,
  }

  This also covers the hard-coded-value deduction. I compiled the bare patterns,
  without your arm bodies, in a scratch file on 1.71.0 with no warnings. Here's
  how they sort test lines:

  ┌──────────────┬──────────────────────────────────────────────────────────┐
  │     Line     │                      Arm it matches                      │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ ""           │ blank                                                    │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ [scene]      │ missing title                                            │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ [scene]  A   │ title, with "A b" from title.join(" ")                   │
  │  b           │                                                          │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ x.txt        │ config file, extra empty                                 │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ x.txt y z    │ config file, 2 extra tokens, so whinge                   │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ [Scene] t    │ config file, because the comparison is case-sensitive as │
  │              │  the spec says                                           │
  └──────────────┴──────────────────────────────────────────────────────────┘

❯ wait so for exit, say we have fragments A B C, C will exit all, B exits w/o   
  C's and A exits w/o B's. but couldnt A include C's?                           

⏺ Yes, A can include players from C, and the code still handles them correctly.
  Exits and entrances only ever compare neighboring fragments, so a character
  like that exits and then enters again.

  Say X is in A and C but not in B:

  A:  X, Y        → exit(B): X isn't in B, so "[Exit X.]"
  B:  Y, Z        → enter(A): Z is new, so "[Enter Z.]"   (X isn't on stage)
                  → exit(C): Y and Z aren't in C, so "[Exit Z.]" "[Exit Y.]"
  C:  X           → enter(B): X wasn't in B, so "[Enter X.]"
                  → exit_all: "[Exit X.]"

  That's what you'd want on a real stage. X can't stay on stage through B
  without being in B. X walks off after A and comes back for C. Looking at C
  when A exits would leave X on stage, silent, through all of B.

  The spec words it in terms of the next fragment only: "the exit of any
  character that is not in the subsequent scene fragment". Entrances work the
  same way, looking only at the previous fragment.

  There's a related quirk with scene boundaries. Neighboring fragments are
  compared even when a [scene] line sits between them. If someone is in the last
  fragment of Scene I and the first fragment of Scene II, they never exit or
  re-enter across the scene change, even though the setting moves. The Hamlet
  example doesn't hit this, because Polonius and Ophelia are replaced entirely
  in II.2. The spec calls this "a simple version of character entrances and
  exits" that Lab 3 will extend, so follow the spec for now. The quirk is worth

⏺ The parser rejects line 104 because a match guard (if …) can't go inside a
  pattern. A guard belongs to the whole arm and always comes after the complete
  pattern:

  pattern if condition => ...

  Putting it inside ( … ) as part of None | … isn't valid syntax. The parser
  then tries to read if as a variable name, which is why you see the odd
  follow-on errors like "variable if is not bound".

  Fix: split it into separate arms. You want separate error messages for the two
  failures anyway:

  match self.fragments.first() {
      None => { /* no fragments: eprintln + Err */ }
      Some(first) if <first has no title> => { /* untitled: eprintln + Err */ }
      Some(_) => Ok(()),
  }

  If you do want one arm for both, the guard has to go at the end of the arm and
  cover both cases, which gets awkward. Two arms is clearer.

  The function has a few more problems that will show up once it parses:
  1. Nothing is returned. prepare returns Result<(), u8>, but the match arms
     evaluate to (). Make the match the last expression with no semicolon, and
     have each arm return Err(...) or Ok(()).

     play.rs, so you'll get E0616. That's the has_title() method or pub(crate)
