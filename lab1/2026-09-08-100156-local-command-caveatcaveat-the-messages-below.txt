❯ when is it Error: 2 vs Error: 3                                               

  Ran 1 shell command (ctrl+o to expand)

⏺ There is no Error: 3 — your program only ever returns 1 or 2. The spec defines
  exactly two codes, and declarations.rs:12-13 matches:

  - Error: 1 — ERR_BADLY_FORMED_COMMAND_LINE. Only from parse_args (main.rs:21
    and :27): no config file name, more than three arguments, or a third
    argument that isn't exactly whinge. Always accompanied by the usage message.
  - Error: 2 — ERR_FAILED_TO_GENERATE_SCRIPT. Three distinct causes, each with
    its own message: the config file won't open (script_gen.rs:128), the config
    has fewer than two non-blank lines (:136), or no character's part file could
    be read (:104).

  If what you're actually looking at is the process exit status, note it's
  always 1 on failure, never 2 — Rust's Termination impl for Result<(), u8>
  prints Error: {code} to stderr and exits 1 regardless of the value. So a
  script-generation failure looks like Error: 2 on stderr but $? == 1. That's
  why run_tests.sh asserts on the Error: N line rather than the exit status;
  it's the same for everyone given the mandated main signature, so nothing to
  fix.
